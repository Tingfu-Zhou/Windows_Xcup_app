这是我早期为了实现飞机杯能和成人视频联动的早期探索。这是个为Windows PC 做的早期程序，公布出来给大家做参考。感兴趣的同好可以跟我联系（QQ：3247499719）

方案如下：

VideoProcessController 是核心的分析控制组件，负责视频帧提取、姿态分析、音频分析、动作融合与蓝牙控制。（本地视频播放分析的界面）

[主循环模块]采用 mediaPlayer.getCurrentTime().toMillis(); 驱动整个音视频分析链路。视频分析线程每 100ms 执行一次，音频分析线程也是100ms执行一次，但音频分析本质上是1秒执行一次。主线程800ms执行一次。

视频分析线程的流程如下：

1. 获取当前播放时间戳 T。

2. 抽取对应时间点的视频帧 [视频抽帧模块]。

3. 提交该帧至姿态检测模型 YOLO-Pose [视频分析推理模块]，完成 COCO 17 关键点提取。
   若检测到多人，仅保留置信度最高者；若关键点质量不足（<40\% 的点置信度 >0.4），则丢弃该帧。

4. 将归一化后的关键点同时送入两个下游模块：
   
   a) 视频节奏估计模块 (VideoRhythmEstimator)：每帧都会调用 onPoseFrame()，模块内部缓冲足够数据后自动执行节奏估计，结果通过 getLatestFreqHz() 等方法拉取并存储到成员变量中。
   
   b) 动作识别滑窗：关键点入队至 poseWindow（容量 32）。当窗口满时，按 stride=8 门控：首次窗口满立即推理，此后每累积 8 帧新数据才执行一次 ST-GCN++ 推理。识别结果存储到 latestVideoAction / latestVideoConfidence 等成员变量中。


音频分析线程：音频分析每隔一秒，读取时间区间 [T-2s, T] 的 32000 点 PCM 信号片段[音频读取模块]，并送入 YAMNet （音频分析模型）进行识别[音频分析推理模块]。同时音频分析线程会将最近 1 秒的音频数据推入音频节奏识别模块 AudioRhythmEstimator，当音频节奏识别模块已缓冲足够数据时，执行节奏估计一次，并将结果存储到原子引用中。

主线程：读取最新的视频与音频分析结果，融合视频与音频结果，生成控制动作并通过蓝牙发送指令[蓝牙模块]。
